# Security model

## Trust boundaries

Caddy is the external boundary. PostgreSQL, MinIO, Temporal, research dependencies, and GPU services are internal-only. Direct research retrieval runs on a dedicated egress network. Firecrawl is split across internal client/backend networks and shares no application or data credentials. Its browser has no direct egress: public DNS is provided through a constrained forwarder and all browser TCP must cross a DNS-pinning proxy which permits only public destinations on ports 80/443. Models receive delimited untrusted source text and no shell, browser-control, publishing, credential, or arbitrary-URL tools.

## Identity and authorization

Local passwords use Argon2id. Authentication uses secure, HTTP-only cookies outside local development and a separate CSRF token. Role checks are enforced in API dependencies and application use cases. Roles are `admin`, `operator`, `editor`, `reviewer`, and `viewer`. Authentication, configuration, approval, provider, upload, and publication activity produces append-only audit records.

Optional OIDC and TOTP do not weaken local policy. TOTP enrollment verifies the current password, shows the secret only before confirmation, stores it encrypted and emits one-use recovery codes whose hashes are retained. OIDC uses Authorization Code with PKCE, ten-minute one-use hashed state, nonce validation, redirect refusal, bounded provider responses, an asymmetric algorithm allowlist, JWKS `kid` selection, and signed `iss`/`aud`/`exp`/`iat`/`sub` validation. The stored subject is an issuer-bound fingerprint. Group/claim mapping is explicit and multi-group privilege order is deterministic. Login failures are durably throttled per normalized identity/client key. Secrets are never returned after creation and are redacted from structured logs and errors.

## Local development secrets

Files ending in `.dev` are known public values for an isolated local stack only. They make `docker compose up` reproducible and are not production credentials. Production operators must mount newly generated `*.local` secret files, restrict their permissions, and use the production override documented in the operator guide.

## Implemented hardening controls

Increment 1 includes strict HTTP(S)-only source targets, URL-credential/private/link-local/metadata blocking, subject domain allow/block policy, a connector that rejects an entire DNS response if any answer is non-public and hands only validated answers to the socket layer, bounded/coalesced robots caching with per-path evaluation, per-hop redirect revalidation, HTTPS-downgrade rejection, verified TLS, MIME/byte/time limits, rejection of unexpected public-body encodings, cookie-free requests, per-domain throttling, hostile HTML isolation, prompt-injection markers, XML entity rejection, encrypted-PDF rejection, PDF page/output ceilings, and structured depth/row/cell ceilings. Firecrawl receives a fixed scrape request with no actions, arbitrary script, selectors, model prompts or credentials. Raw HTTP bodies, rendered DOMs and normalized evidence are separately hashed and immutable. Live discovery stops at pending opportunity review; only a separate approved-opportunity workflow may acquire source candidates into immutable snapshots.

Production API mode disables OpenAPI/docs and enables an explicit Host allowlist. Request schemas reject unknown properties, cookie-authenticated mutations require a CSRF cookie/header match, and evidence links are rendered only when their parsed scheme is HTTP(S).

Workflow monitoring projects only whitelisted Temporal event types and server-owned activity labels; it never returns workflow inputs, activity payloads, raw failure text or credentials. Immutable control records retain the validated non-secret start request, correlation ID and retry parent edge. SSE authenticates through the ordinary session boundary and releases its database connection before streaming.

AI/provider traffic exits only through `editorial-worker`. The gateway accepts configured and visible models only, validates fixed HTTP(S) endpoints without URL credentials/query/fragment, uses no cookies or redirects, bounds response bodies and deadlines, and reads credentials only from safe mounted basenames. Local-only requests cannot reach remote routes; `remote_after_redaction` applies deterministic field replacement before provider serialization. Usage records expose only hashes, categories and paths for removed values. Source/dossier bodies are delimited as untrusted data, prompt templates grant no tools, and trusted editor regeneration instructions cannot relax the evidence/JSON policy. Schema validation, bounded repair, fallback, circuit breakers, concurrency limits and sliding one-minute request limits apply before persistence. Scripts and storyboards cannot progress without exact-version/hash approvals.

YouTube publishing requests only `youtube.upload` and `youtube.force-ssl`, the minimal union needed for video upload plus captions, thumbnail, status reconciliation and scheduling. OAuth uses offline access and a random state whose hash is single-use and expires after ten minutes. Only `publisher-worker` has publishing egress and the OAuth client secret. Its authenticated internal gateway encrypts the refresh token before returning it; plaintext refresh/access tokens and resumable session URIs never enter API responses, Temporal history, audit context or logs. The encryption master key is a separately mounted secret and real uploads remain disabled in the versioned admin configuration. Dry-run and real side-effect keys are distinct, video creation is always private, an encrypted resumable URI is committed before bytes flow, and retries query that URI before resuming. Scheduling requires an independent exact-hash approval and a future UTC time. No code path invokes YouTube deletion.

The edge rejects request bodies larger than 16 MiB and emits a fresh nonce-based script CSP per response. Application services run read-only, as non-root users, with all Linux capabilities dropped, `no-new-privileges`, bounded temporary filesystems, resource limits and graceful stop periods. Application/data/observability/browser-backend networks are internal. Runtime audits verify that Caddy is the only host port and that identity, model-provider and publishing egress networks contain only their authorized service.

The observability profile retains metrics for 30 days, keeps Grafana authenticated, and exposes Grafana only through Caddy. PostgreSQL and MinIO backups are checksummed; the restore drill refuses an existing target, restores into disposable targets, verifies exact object counts and representative database state, then removes those targets. CycloneDX SBOMs cover every resolved Compose image and are protected by a SHA-256 manifest.
