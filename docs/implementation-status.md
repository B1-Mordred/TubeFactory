## Optimization, policy and operations scope

Implemented and verified: append-only analytics snapshots and provenance; deterministic registered-visible-model benchmarks with primary/fallback recommendations; separate reviewer decision and administrator application, with no automatic route mutation; source-freshness and script-originality reports; changed/retracted-source correction cases with affected claim/timecode maps and proposals; versioned fail-closed budgets and idempotent usage; operational-evidence records; and release-time freshness/originality enforcement.

Subject profiles now expose deterministic `assisted`, `supervised` and `trusted` operating policies. High-risk or configured sensitive work always retains human dossier and final-video gates, and publication is never unattended. Manual and discovered opportunities require the explicit editorial rationale “Why does this video deserve to exist?” before shortlist. The rationale and evaluated policy are retained in opportunity, dossier audit, and exact render approval provenance. Evidence-density and repeated-scene policy are pure, tested rules; media QA also compares repeated assets and prior production hashes.

The optional observability profile is live with OpenTelemetry traces, Prometheus application/collector targets, Grafana dashboards/alerts, Loki and Promtail. Caddy enforces a 16 MiB body ceiling and per-response nonce CSP; application containers are read-only, drop all capabilities, use `no-new-privileges`, and have graceful stop periods. Only Caddy publishes a host port; provider, identity and publisher egress are each restricted to their designated service.

LAN discovery is active as `evidence-studio.local`. A hardened, boot-enabled Avahi publisher maps that application hostname and its `_http._tcp` service to the host's current DHCP IPv4 address, monitors lease-address changes, and preserves the existing localhost entry path. Caddy and the API allowlist both recognize the distinct LAN hostname.

The LAN UI is real-browser verified. Nonce-based CSP now forces dynamic Next.js rendering so every framework/bootstrap script receives the request nonce, while `upgrade-insecure-requests` is emitted only for actual HTTPS requests. This prevents the HTTP LAN endpoint from rewriting its own JavaScript and CSS requests to unavailable HTTPS. The core smoke gate checks both properties to prevent recurrence.
